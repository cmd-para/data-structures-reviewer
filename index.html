Module 01

Linear Data Structures

Elements are arranged sequentially, where each element is attached to its previous and/or next adjacent element.

1

Arrays

An Array is a collection of homogeneous elements stored in contiguous memory locations. Because elements sit side-by-side in RAM, any element's memory address can be computed directly using its index: Address = Base_Address + (Index × Element_Size).

Advantages

  • O(1) Random Access: Instant lookup by index.
  • Cache Locality: Contiguous memory maximizes CPU cache hits.
  • Zero Pointer Overhead: Only stores raw data values.

Disadvantages

  • Fixed Size (Static): Resizing dynamic arrays requires O(n) copying.
  • O(n) Middle Insert/Delete: Requires shifting subsequent elements.
  • Unsorted Search: Linear scan takes O(n) time.
2

Matrices (2D Arrays)

A Matrix is a two-dimensional grid of size R × C (Rows × Columns). Although visualized as a 2D table, computer RAM is 1-dimensional, so matrices are flattened using either Row-Major or Column-Major ordering.

Memory Flattening Orders

  • Row-Major (C, C++, Python, Java): Stores row 0 completely, then row 1, etc.
    Offset = (r × NumCols) + c
  • Column-Major (Fortran, MATLAB, R): Stores column 0 completely, then column 1, etc.
    Offset = (c × NumRows) + r

Common Operations & Complexity

  • • Element Access M[r][c]: O(1)
  • • Traversal / Transpose: O(R × C)
  • • Standard Matrix Multiplication (N×N): O(N³)
  • • Use Cases: Image pixels, Graph Adjacency Matrices, Dynamic Programming tables.
3

Stacks (LIFO)

A Stack follows the LIFO (Last-In, First-Out) principle—like a stack of plates. Insertions and deletions happen strictly at one end called the TOP.

push(x)
Add to top • O(1)
pop()
Remove top • O(1)
peek()
View top • O(1)

Key Applications: Function Call Stack (recursion), Undo/Redo history, Bracket/Syntax balancing, Depth-First Search (DFS), Postfix expression evaluation.

Edge Errors: Stack Overflow (pushing onto a full fixed-capacity stack) and Stack Underflow (popping from an empty stack).

4

Queues (FIFO)

A Queue follows the FIFO (First-In, First-Out) principle—like a checkout line. Elements enter at the REAR (Tail) via enqueue and leave from the FRONT (Head) via dequeue.

enqueue(x)
Add to rear • O(1)
dequeue()
Remove front • O(1)
front()
View front • O(1)

Variants:

  • Circular Queue: Connects rear back to front using modulo arithmetic (rear + 1) % capacity to prevent wasted array slots.
  • Priority Queue: Dequeues highest-priority element first (typically built with a Binary Heap).
  • Deque (Double-Ended Queue): Allows O(1) insertion/removal at both front and rear.

Use Cases: Breadth-First Search (BFS), CPU task scheduling, printer spoolers, message buffers.

Linked Lists

A Linked List is a dynamic linear collection of Nodes scattered in memory. Each node stores data plus one or more pointers/references linking to adjacent nodes.

Singly Linked List

Each node has data and next. Forward traversal only. Low memory overhead (1 pointer/node).

Doubly Linked List

Each node has prev, data, and next. Bidirectional traversal & O(1) deletion given a node reference.

Circular Linked List

The last node's next points back to HEAD instead of null. Great for round-robin scheduling.

Module 02

Advanced Data Structures

Non-linear and associative structures engineered for rapid O(1) or O(log n) lookup, insertion, and hierarchical organization.

1

Hash Tables (Hash Maps)

A Hash Table stores Key–Value pairs and achieves average O(1) search, insert, and delete time by passing the key through a Hash Function index = hash(key) % table_size to find its bucket index in an underlying array.

Type a key to compute its bucket index...

Collision Resolution Strategies

A collision occurs when two distinct keys hash to the exact same bucket index.

  • Separate Chaining: Each bucket stores a Linked List (or balanced tree) of all colliding entries.
  • Open Addressing (Probing): Finds another open slot inside the array itself via Linear Probing (h + i), Quadratic Probing (h + i²), or Double Hashing.

Load Factor & Worst-Case O(n)

  • Load Factor (α): α = n / m (stored items ÷ bucket count).
  • Rehashing: When α exceeds a threshold (e.g., 0.75), the table doubles in size and re-hashes all keys to preserve O(1) speed.
  • Worst Case O(n): Happens if a poor hash function maps all keys into a single bucket (degenerating into a linked list).
2

Binary Search Tree (BST)

A Binary Search Tree is a rooted binary tree that enforces the BST Invariant for every node N: All keys in N's left subtree < N.key < All keys in N's right subtree.

Balanced BST (Height h = 2)

Depth-First Tree Traversals (on example tree)

  • Inorder (Left, Root, Right): 20, 30, 40, 50, 60, 70, 80 (Always yields sorted ascending order!)
  • Preorder (Root, Left, Right): 50, 30, 20, 40, 70, 60, 80 (Used to clone/serialize a tree)
  • Postorder (Left, Right, Root): 20, 40, 30, 60, 80, 70, 50 (Used to delete/free nodes bottom-up)

3 Cases of BST Deletion

1. Leaf Node (0 children): Simply remove it.

2. One Child: Bypass node and link its parent directly to its child.

3. Two Children: Replace node's value with its Inorder Successor (smallest key in right subtree) or Inorder Predecessor, then delete that duplicate.

Complexity Note: Time is O(h) where h is tree height. Balanced BSTs have h = O(log n). Inserting already-sorted data creates a degenerate skewed BST (essentially a linked list) with h = O(n).
